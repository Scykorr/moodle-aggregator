# Руководство по работе с MoodleConfigurator.exe

## 1. Назначение

**MoodleConfigurator** — программа с графическим интерфейсом для настройки развёрнутого в Docker Moodle без ручного редактирования файлов:

- смена IP / URL (`wwwroot`);
- HTTP-порт;
- имя сайта;
- язык;
- учётные данные администратора (в `.env` и сброс пароля в работающем Moodle);
- старт / стоп контейнеров и просмотр статуса.

## 2. Сборка EXE (на ПК с Python)

Требуется Python 3.10+.

```powershell
cd configurator
.\build.ps1
```

Результат: `configurator\dist\MoodleConfigurator.exe` (один файл, без консоли).

Зависимости только для сборки: PyInstaller. Интерфейс использует встроенный **tkinter**.

## 3. Куда положить EXE

Программа ищет `docker-compose.yml` в:

1. каталоге, где лежит EXE;
2. родительском каталоге;
3. каталоге на уровень выше (`project/`, если EXE в `configurator\dist`).

Рабочие схемы:

- оставить EXE в `configurator\dist\` внутри проекта;
- или скопировать EXE в корень проекта рядом с `docker-compose.yml`.

Рядом должен быть актуальный файл `.env` (или `.env.example` для первого заполнения).

## 4. Требования при запуске

- Установленный и **запущенный** Docker Desktop;
- уже импортированные / собранные образы (`moodle-offline:5.2`, `mariadb:11.4`);
- права на запись в каталог проекта (сохранение `.env`).

## 5. Описание экрана

| Поле / кнопка | Назначение |
|---------------|------------|
| **Каталог проекта** | Найденный корень со `docker-compose.yml` |
| **IP / хост (LAN)** | Список локальных IPv4; можно вписать вручную |
| **Обновить IP** | Повторно опросить сетевые интерфейсы |
| **HTTP-порт** | Проброс порта хоста (`MOODLE_HTTP_PORT`), по умолчанию `80` |
| **wwwroot (URL)** | Полный адрес Moodle, например `http://192.168.0.10` |
| **Собрать URL из IP+порт** | Автозаполнение `wwwroot` |
| **Полное / короткое имя сайта** | Отображаемое имя LMS |
| **Язык** | Код языка установки/настроек (`ru`, `en`, …) |
| **Админ / пароль / email** | Значения для `.env`; пароль также для кнопки смены в Moodle |
| **Применить и перезапустить** | Сохранить `.env`, пересоздать контейнер `moodle`, обновить `config.php`, сбросить кэш |
| **Только сохранить .env** | Запись файла без перезапуска Docker |
| **Старт / Стоп** | `docker compose up -d` / `stop` |
| **Обновить статус** | `docker compose ps` и текущий `wwwroot` |
| **Сменить пароль админа** | CLI `reset_password.php` внутри контейнера `moodle_app` |

## 6. Типовой сценарий после переноса на другой ПК

1. Выполните `scripts\import-and-start.ps1`.
2. Запустите `MoodleConfigurator.exe`.
3. Нажмите **Обновить IP**, выберите IP этого сервера в LAN.
4. Нажмите **Собрать URL из IP+порт** (проверьте порт).
5. При необходимости измените имя сайта и пароль админа.
6. Нажмите **Применить и перезапустить** и дождитесь сообщения об успехе.
7. На клиентских компьютерах откройте тот же URL, что в поле **wwwroot**.

## 7. Смена только IP

1. Выберите новый IP → **Собрать URL** → **Применить и перезапустить**.
2. Сообщите пользователям новый адрес.
3. Старые закладки со старым IP работать корректно не будут.

## 8. Смена пароля администратора

1. Введите логин (обычно `admin`) и **новый** пароль.
2. Убедитесь, что контейнер Moodle запущен (кнопка **Обновить статус**).
3. Нажмите **Сменить пароль админа**.
4. Пароль также записывается в `.env` как `MOODLE_ADMIN_PASSWORD`.

> Поле пароля в форме при **первой установке** используется entrypoint’ом. Если Moodle уже установлен, смена пароля только через кнопку «Сменить пароль админа» (или веб-интерфейс Moodle).

## 9. Сообщения об ошибках

| Сообщение / ситуация | Действие |
|----------------------|----------|
| «Дождитесь завершения…» | Идёт долгая операция Docker — подождите |
| Не найден `docker` | Установите/запустите Docker Desktop |
| Не удалось сменить пароль | Контейнер `moodle_app` не запущен или установка ещё не завершена |
| Пустой статус / exit 127 | Docker не в PATH для GUI-сессии — перезапустите Docker и программу |
| Сайт открывается, но «не тот адрес» | `wwwroot` ≠ URL в браузере — снова примените настройки |

## 10. Запуск без EXE (для отладки)

```powershell
cd configurator
python moodle_configurator.py
```

## 11. Ограничения

- Утилита управляет стеком через `docker compose` в найденном каталоге проекта; другие compose-проекты не затрагивает.
- Смена порта на занятый (например, 80 занят IIS) приведёт к ошибке Docker — выберите свободный порт и укажите его в URL (`http://IP:8080`).
- Для HTTPS / доменного имени укажите полный URL в **wwwroot** вручную (и настройте сертификат отдельно — в базовом пакете HTTP).
