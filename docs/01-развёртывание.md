# Руководство по развёртыванию Moodle (Docker, офлайн / LAN)

## 1. Назначение

Развернуть **Moodle 5.2** в Docker так, чтобы:

- сервис работал на одном компьютере-сервере в локальной сети;
- клиенты открывали Moodle по адресу `http://IP_сервера/` **без доступа в интернет**;
- весь стек можно было перенести на другой компьютер (USB / внешний диск).

## 2. Требования

### ПК для первичной сборки (нужен интернет)

- Windows 10/11 (64-bit)
- Docker Desktop с включённым WSL2 / Linux engine
- не менее **8 ГБ RAM**, лучше 16 ГБ
- **20+ ГБ** свободного места (исходники + образы)

### Целевой ПК (может быть без интернета)

- Windows 10/11 + Docker Desktop (установщик `.exe` подготовьте заранее)
- те же рекомендации по RAM/диску
- статический или известный IP в локальной сети

## 3. Структура проекта

```
moodle/
  docker-compose.yml
  Dockerfile
  .env / .env.example
  docker/                 # entrypoint, Apache
  scripts/                # export / import / stop
  configurator/           # GUI и сборка EXE
  docs/                   # это руководство
  transfer-package/       # появляется после export
```

## 4. Первичная сборка (с интернетом)

### 4.1. Подготовка

1. Установите Docker Desktop и дождитесь статуса *Running*.
2. Откройте PowerShell в каталоге проекта.
3. Создайте файл окружения:

```powershell
copy .env.example .env
```

При необходимости отредактируйте `.env` (пароли, имя сайта).
**Важно:** `MOODLE_WWWROOT` должен совпадать с URL, по которому будут заходить пользователи (например `http://192.168.1.50`).

### 4.2. Сборка и запуск

```powershell
docker compose build
docker compose up -d
docker compose ps
docker compose logs -f moodle
```

Первый запуск выполняет CLI-установку Moodle (может занять несколько минут). Когда в логах появится `Starting Apache`, откройте сайт в браузере.

Учётка администратора по умолчанию:

- логин: значение `MOODLE_ADMIN_USER` (обычно `admin`)
- пароль: `MOODLE_ADMIN_PASSWORD` (по умолчанию `Admin123!`)

### 4.3. Доступ из локальной сети

1. Узнайте IP сервера (`ipconfig`) или используйте **MoodleConfigurator**.
2. Установите `MOODLE_WWWROOT=http://<IP>` (и порт, если не 80).
3. Пересоздайте контейнер Moodle или нажмите «Применить» в конфигураторе.
4. На клиентских ПК откройте тот же URL. Брандмауэр Windows: разрешите входящие TCP на порт HTTP (по умолчанию 80).

> Moodle требует, чтобы адрес в браузере **точно совпадал** с `wwwroot`. Иначе будут редиректы и ошибки входа.

## 5. Подготовка пакета для переноса

На ПК со **уже работающим** Moodle (скрипт сохраняет текущие образы и volumes, без rebuild/pull):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\export-for-transfer.ps1
```

Создаётся каталог `transfer-package/`:

```
transfer-package/
  IMPORT-AND-START.cmd
  PACKAGE_INFO.txt
  images/
    moodle-offline-5.2.tar
    mariadb-11.4.tar
  volumes/
    moodle_db_data.tgz      # база (пользователи, курсы, настройки)
    moodle_data.tgz         # moodledata (в т.ч. языковой пакет ru)
  extras/                   # запасной ru.zip, если был найден
  project/                  # compose, .env, scripts, docs...
```

Скопируйте **весь** `transfer-package` на USB. Размер — порядка нескольких гигабайт.

На целевом ПК **не** запускайте `docker compose build` и `docker compose pull`.

## 6. Развёртывание на целевом ПК (без интернета)

1. Установите Docker Desktop **из заранее скачанного установщика** и дождитесь статуса Running.
2. Скопируйте **целиком** папку `transfer-package` на диск.
3. Запустите `IMPORT-AND-START.cmd` (или из `project\scripts`: `import-and-start.cmd`).

Скрипт загрузит образы, восстановит volumes и поднимет тот же сайт (язык, учётки, данные).

4. Откройте `http://localhost/`. Если с других ПК — задайте `MOODLE_WWWROOT=http://<IP>` и пересоздайте сервис moodle.
5. Проверьте вход той же учёткой, что на исходном ПК.

Остановка:

```powershell
.\scripts\stop.ps1
```

Полное удаление данных (осторожно):

```powershell
.\scripts\stop.ps1 -RemoveVolumes
```

## 7. Смена IP после переноса

При смене IP сервера **обязательно** обновите `wwwroot` (через конфигуратор или вручную в `.env` + `docker compose up -d --force-recreate moodle`).
Иначе ссылки и вход будут вести на старый адрес.

## 8. Типовые проблемы

| Симптом | Что проверить |
|---------|----------------|
| Сайт не открывается с других ПК | Брандмауэр, IP, порт в `MOODLE_HTTP_PORT`, контейнеры `docker compose ps` |
| Редирект / «wrong wwwroot» | `MOODLE_WWWROOT` должен совпадать с URL в браузере |
| Долгий первый старт | Нормально: идёт install.php; смотрите `docker compose logs -f moodle` |
| `docker load` / `compose` не найдены | Docker Desktop не запущен или не в PATH |
| Нет места на диске | Образы + volumes занимают много ГБ |

## 9. Безопасность (кратко)

- Смените пароли в `.env` до вывода в продакшен-класс LAN.
- Не публикуйте порт Moodle в интернет без HTTPS и жёсткой политики.
- Файл `.env` содержит секреты — не выкладывайте его в открытый доступ.
