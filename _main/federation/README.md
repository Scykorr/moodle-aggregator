# Федерация Moodle

Единый вход в независимые Moodle через Keycloak, без Active Directory.
Исходный стек опубликован первым коммитом `91961fe` в
[Scykorr/moodle-aggregator](https://github.com/Scykorr/moodle-aggregator).

## Что готово

- `compose.aggregator.yml` / `web/`: **основной агрегатор в Docker с веб-интерфейсом**,
  редактированием списка HTTP(S)-серверов, фоновыми проверками и постоянным томом.
- `start-gui.pyw` / `server_manager.py`: предыдущий настольный интерфейс,
  оставлен как дополнительная локальная утилита.
- `compose.yml`: отдельный Keycloak + PostgreSQL, HTTPS, отдельный volume.
- `sites.example.json`: реестр Moodle в нескольких подсетях.
- `prepare.py`: проверка реестра, генерация realm, отдельного OAuth-клиента и
  случайного секрета для каждого Moodle, локального файла настроек.
- `probe.py`: проверка DNS/IP, TLS и discovery сервера входа.
- [Варианты и архитектура](docs/architecture.md).
- [Развёртывание и подключение Moodle](docs/deployment.md).
- [Существующие аккаунты и приёмочные проверки](docs/migration.md).
- [Результаты проверки комплекта](docs/verification.md).

Это комплект для развёртывания, а не уже подключённая сеть: реальные адреса,
сертификаты и младшие версии Moodle пока неизвестны. На действующих Moodle
настройки не изменялись. Примерные версии `3.11`, `4.5`, `5.2` не являются
результатом обследования серверов пользователя.

## Начало работы

### Веб-интерфейс в Docker (основной способ)

Из этой папки:

```powershell
docker compose -f compose.aggregator.yml up -d --build
```

Откройте **http://localhost:8088**. Добавляйте строки, вводите адреса,
проверяйте один или все серверы. Кнопка «Сохранить список» сохраняет изменения;
перед проверкой список сохраняется автоматически. Адреса хранятся в Docker volume,
общем для всех браузеров, и сохраняются при пересоздании контейнера.

Подробности запуска из LAN, пароля, переноса и диагностики:
[Docker-агрегатор](docs/web-aggregator.md).

### Настольная утилита (предыдущий вариант)

На Windows откройте двойным щелчком `start-gui.pyw` (нужен Python с Tkinter),
либо выполните из этой папки:

```powershell
python server_manager.py
```

Нажмите «Добавить сервер» для каждой новой строки. Можно ввести просто IP
(`10.30.0.10`, автоматически используется HTTP), адрес с портом
(`http://10.40.0.10:8080`) или HTTPS-адрес, в том числе с путём `/moodle`.
«Проверить» проверяет строку, Enter в адресе делает то же самое;
«Проверить все» запускает проверки непустых строк. Список прокручивается,
количество строк не фиксировано. Одновременно выполняются до шести запросов.

Зелёный результат означает наличие характерных признаков Moodle в HTML.
Жёлтый — сервер отвечает, но Moodle не подтверждён либо доступ ограничен.
Красный — некорректный адрес, ошибка HTTP, DNS, TLS или соединения.
После редиректа показывается конечный URL. Ответ HTTP 200 и простое упоминание
слова Moodle не считаются подтверждением Moodle. Проверяется до 1 МиБ HTML;
нестандартная тема или шлюз авторизации могут скрыть признаки платформы.

«Сохранить список» записывает адреса локально в `servers.local.json`; при новом
открытии они восстанавливаются. Пустые строки не сохраняются. Перед закрытием
сохраните изменения кнопкой. Этот файл исключён из Git, результаты проверок
не сохраняются как постоянный статус доступности. Запросы идут напрямую с
текущего ПК, без прокси из переменных окружения; настройка серверов не меняется.
Таймаут сетевой операции — 6 секунд, редиректы ограничены. Суммарное время при
редиректах/медленном DNS может быть больше, окно при этом остаётся доступным.

HTTP разрешён для обнаружения. Подключение SSO по-прежнему требует HTTPS:
список обнаруженных серверов не перезаписывает `sites.json` и не меняет realm.
Версии, подсети и параметры SSO заполняются после обследования серверов.

### Развёртывание SSO

Из этой папки, Python 3.10+ и Docker Compose v2:

```powershell
Copy-Item sites.example.json sites.json
# Отредактировать sites.json: версии, IP, подсети, канонические HTTPS URL.
python prepare.py --validate-only
python prepare.py
# Подготовить certs/server.crt и certs/server.key по инструкции.
docker compose --env-file generated/.env config --quiet
docker compose --env-file generated/.env up -d
python probe.py --ca certs/ca.crt
```

Не запускайте примерные адреса как боевую конфигурацию. Файл `sites.json`,
папки `generated/` и `certs/` исключены из Git. Генератор не отправляет данные
по сети и не перезаписывает существующий `generated/`.

## Проверки разработчика

```powershell
python -m unittest discover -s tests -v
python prepare.py --config sites.example.json --validate-only
```

Проверки покрывают неверные версии, адреса и подсети, изоляцию клиентов,
случайные секреты, защиту от перезаписи и неверный OIDC issuer.
Полный вход студента на реальных Moodle проверяется отдельно по плану миграции.

Дополнительный интеграционный тест требует Docker и OpenSSL:

```powershell
python tests/smoke_identity.py --openssl 'C:\Program Files\Git\usr\bin\openssl.exe'
```

Он запускает отдельный временный проект на свободном localhost-порту, проверяет
настоящий TLS, discovery и импорт клиента через Admin API. Затем удаляет только
свои контейнеры и volume. Образы остаются в Docker cache. На Linux/macOS обычно
достаточно `python tests/smoke_identity.py`, если `openssl` есть в PATH.
