# Подключение существующих студентов без потери обучения

## Пилот

1. Уточните полный релиз каждого Moodle и создайте резервную копию БД,
   `moodledata`, кода и конфигурации. Восстановите копию на изолированном стенде.
2. Выберите 2–3 тестовых студентов. Зафиксируйте локальный `user.id`, курсы,
   зачисления, оценки и попытки на каждом сайте, без публикации этих сведений.
3. Заведите центральные аккаунты Keycloak или импортируйте утверждённый реестр
   организационным процессом. Сопоставляйте по стабильному учебному идентификатору;
   одинаковые ФИО не доказывают, что это один человек.
4. Разберите конфликтующие логины, дубли email и несколько аккаунтов одного
   студента на одном Moodle вручную. Общие семейные email для автоматической
   привязки не подходят. Не переносите хеши паролей между разными Moodle/Keycloak.
5. На время пилота включите запрет создания аккаунтов при аутентификации в
   Moodle. Студент входит прежним способом в существующую запись и через
   «Настройки → Связанные входы» добавляет «Единый аккаунт», подтверждая вход
   в свой Keycloak. Пройдите подтверждение почты, если его требует этот релиз.
6. Выйдите, войдите через SSO и убедитесь, что локальный `user.id` прежний,
   все результаты обучения сохранены и новая запись не появилась.

Связывание поддерживается штатным механизмом
[Linked logins](https://docs.moodle.org/405/en/Linked_logins).
Не привязывайте чужие аккаунты SQL-запросами по совпадению email и не включайте
пропуск подтверждения email без проверенного владения адресами. Для массовой
миграции нужен отдельный сверенный реестр и инструмент под точный релиз Moodle;
в этом проекте автоматическая миграция реальных пользователей не выполняется.

## Новые студенты

После привязки старых аккаунтов разрешите автоматическое создание пользователей
через OAuth 2 на сайтах, где это требуется. Студент заводится в Keycloak один раз;
первое посещение Moodle создаёт только локальный профиль. Зачисление на курсы
настраивается отдельно существующими средствами Moodle. Саморегистрацию по
email в каждом Moodle отключайте согласно принятой политике, чтобы студенты
не заводили параллельные логины.

Старые способы входа не удаляйте массово до проверки всех привязок. Наличие
локального пароля у прежней записи может сохранить обход центральной блокировки:
при переводе на обязательный SSO это надо отдельно устранить поддерживаемым
способом для фактического Moodle. Аварийные локальные администраторы сохраняются.

## Приёмочная матрица

Выполнить на фактических релизах 3.x, 4.x и 5.x, из каждой студенческой подсети.

| Сценарий | Ожидаемый результат |
|---|---|
| Первый центральный вход | Корректная учётная запись и профиль, без ручной повторной регистрации |
| Переход на другой Moodle и нажатие кнопки SSO | Keycloak использует текущую браузерную сессию без повторного пароля |
| Вход существующего студента после привязки | Прежний local user.id и все оценки/курсы |
| Изменение имени/email в Keycloak | Привязка сохраняется, не создаётся дубль |
| Попытка входа другим пользователем с похожим email | Нет привязки к чужим результатам |
| Студент с отсутствующим/неподтверждённым email | Явный процесс подтверждения, без захвата существующего аккаунта |
| Пользователь без зачисления | Не получает доступ к закрытым курсам только из-за SSO |
| Блокировка в Keycloak | Новый центральный вход запрещён; активные локальные сессии проверены отдельно |
| Локальная блокировка в Moodle | SSO не восстанавливает запрещённый доступ |
| Logout в одном Moodle | Зафиксировано поведение других Moodle и IdP; нет обещания глобального logout |
| Недоступность Keycloak | Существующие Moodle-сессии проверены, доступен аварийный администратор |
| Рестарт Keycloak и БД | Те же пользователи, sub и client secrets, volume сохранён |
| Восстановление резервной копии | Сохранены identity links; тестовый студент снова входит |
| Чужой callback / недоверенный TLS | Вход отклонён |

`probe.py` не заменяет эти сценарии. В репозитории нет доказательства
успешного сквозного входа на пользовательских серверах, пока матрица не выполнена.

## Откат

При ошибке пилота отключите новый OAuth-сервис на затронутом Moodle и используйте
сохранённый прежний вход. Не удаляйте пользователей или оценки. Если изменялись
данные, восстановление делайте по согласованной точке с учётом новых результатов,
полученных после резервной копии. Не пересоздавайте Keycloak realm: это меняет
идентичности и может затронуть уже подключённые сайты.
